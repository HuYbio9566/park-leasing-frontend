## 2. 业务流程与边界

| 需求 | 需求文档规定的链路 | 异常及待确认边界 |
| --- | --- | --- |
| REQ-MEETING-001 · 游客浏览 | 会议室入口 → 图片、容量、配置、收费说明 | 内容缺失展示占位；游客不能进入预约时间选择页 |
| REQ-MEETING-002 · 管理员预约 | 登录、绑定企业、取得权限 → 选择会议室 → 日期时段 → 用途和人数 → 提交 → 生成记录并通知用户与物业 | 时段冲突、权限不足阻止提交；物业审核及是否增加企业审批节点待确认 |
| REQ-MEETING-003 · 我的会议 | 查看本人或企业预约 → 查看详情 → 按规则修改或取消 → 同步状态与操作记录 | 超过时限提示不可操作；取消、费用调整、退款和时段释放条件待确认 |
| REQ-MEETING-004 · 物业维护 | 物业权限校验 → 配置会议室、价格、权益和耗材 → 维护订单 → 前台同步并记日志 | 必填规则缺失不能发布；价格生效、耗材确认与订单处理细则待确认 |

公共约束：

- 公开会议室介绍与受保护预约流程分开；“未登录隐藏园区服务区”不等于禁止从公开快捷入口查看会议室介绍。
- 权限依据登录状态、企业绑定、角色和服务权限共同判断，后端校验为准；按园区、企业和角色隔离数据。退出登录后受保护页面不能直接访问。
- 审批需明确提交、通过、驳回、撤回、超时及重新提交的条件、通知和日志；不得直接套用演示预约状态充当完整审批状态机。
- 当前支付规则允许展示预收单，支付后置。收款主体、订单状态、退款责任及发票方式未确认前不进入支付开发，不能把演示提交或跳转返回当作支付成功。
- 会议室和订单维护属于网页驾驶舱；不默认加入小程序。现有三方清单没有明确会议室专用接口契约，不假设已接入门禁或自动开门。

## 3. 现有页面与待补齐部分

本次源码检查范围为上述 V03 目录中的 `miniprogram-view-v3.html`、`miniprogram-store.js` 及 `miniprogram-services.js` 的相关部分，并核对会议室修复提交；不是全部代码审计。

### 已有源码证据

- 首页有“会议室”和“我的会议”入口；会议室列表包含区域、人数、类型筛选控件以及房间图片、位置、容量、设施、价格展示。
- 页面包含会议室详情、日期时段选择、确认预约、结果展示、我的预约及预约详情；HTML 内还有动态预约表单逻辑，不能仅根据初始静态 HTML 判断最终交互。
- `MiniStore.data.bookings` 保存本地预约，通过 `localStorage` 持久化；另有两条示例预约。新增记录使用“本地演示预约”状态，不等于后台已接收。
- 内联脚本包含本机时段冲突检查、过期时段检查、预约编辑和取消、浏览器存储失败提示。详情按状态显示修改或取消操作；这些不是服务端并发占用、真实业务审批或数据隔离能力。
- 会议室返回按钮修复已保存在 `0ee410f`；当前工作树也包含这项改动。本次未重复进行浏览器返回操作验收。

### 建议补齐或核验

1. 公开介绍与预约权限拦截：游客、未绑定企业、无服务权限、退出登录后的直达访问。
2. 预约表单与规则：用途、人数、容量上限、可预约日期、连续时段、预约时长限制，逐项核对需求；不要把静态示例日期和价格作为正式规则。
3. 真实占用与提交：后台忙闲数据、并发冲突、重复提交、提交失败恢复及可靠记录编号。
4. 费用与权益说明：免费额度、计费单位、费用明细、预收单与人工处理入口；支付和退款闭环继续等待确认。
5. 我的会议：本人／企业记录范围、审批进度、修改／取消条件、失败提示、操作记录与真实通知。
6. 物业端：会议室配置、价格权益、耗材确认、审核和订单管理，由驾驶舱独立承接。
7. 通用状态：无权限、空列表、无可用时段、加载失败、数据失效和保存失败。现有部分演示状态应先验证再复用，不宣称全部缺失或全部完成。
