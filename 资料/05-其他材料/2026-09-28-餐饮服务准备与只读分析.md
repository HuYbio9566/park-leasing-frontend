## 2. 业务流程与缺口

餐饮当前定位为“后续批次，待支付和接口确认”，并非已冻结的一期开发范围。

| 业务文档明确的流程异常与待补环节 |                                                     |                                     |
| ---------------- | --------------------------------------------------- | ----------------------------------- |
| 每日订餐             | 菜单已发布 → 查看菜品、价格、截止时间 → 截单前选菜 → 确认订单 → 支付或记账 → 生成取餐码 | 截单拒绝下单；支付、退款、餐厅对账及具体订单状态待定          |
| 智能柜取餐            | 订单成功 → 生成取餐码 → 绑定正确柜口                               | 柜口绑定失败转人工；实际开柜、取餐完成回传和码失效规则未定义      |
| 接待用餐             | 包间、餐标已配置 → 填写人数、餐标、联系方式 → 提交意向 → 物业查看并跟进            | 信息不全禁止提交；押金仅作说明，收取与退款待确认；未规定审批链     |
| 自助餐券             | 已购券 → 物业后台扫码或录入 → 校验 → 核销 → 留痕                      | 重复券、过期券拒绝；券状态与核销人可查；购券、发券和收款规则未完整定义 |

共同前置条件：登录、企业绑定和服务授权；订单与意向按园区、企业、用户及角色隔离。涉及金额的页面还需明确金额来源、失败重试、退款及人工处理入口。

## 3. 现有页面与缺失页面

源码核对发现：

- 已有首页“订餐服务”入口和 `#restaurant` 餐厅展示页。
- 餐厅页展示“今日菜单／本周菜单／我的订单”、两种套餐和预订按钮。
- 上述标签和预订按钮均被共享脚本绑定为“该服务暂未开通”，不是可用订餐流程。
- 共享 `MiniStore` 没有餐饮订单、取餐码、接待意向或餐券数据。
- 当前身份切换主要控制展示，不构成真实权限校验，也没有餐饮物业处理视图。

缺失的业务界面包括：

1. 可操作菜单、订单确认、提交结果、订单列表与详情。
2. 取餐码、柜口状态及人工处理状态。
3. 接待意向表单、提交结果、意向详情与物业跟进。
4. 餐券状态展示、物业扫码／录入核销、核销结果与记录。

菜单维护、餐标配置、购券发券是否由现有餐厅系统承担，需先确认，不能直接扩展成新后台。
